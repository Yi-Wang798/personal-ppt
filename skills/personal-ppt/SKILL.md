# 个人可编辑 PPT

先确定用户确认的母版，再派生每页设计图和原生 PPT。设计图是主要参考而非唯一答案；真实证据、可读性、无溢出与匀称优先。尽量还原风格与主要视觉关系；原图比例不同或参考本身有排版错误时，按 [灵活排版](references/adaptive-layout.md) 主动纠正并记录局部调整，不能机械复刻缺陷。固定外框、文字层级与字号统一；内容区按证据选择不同布局，统一风格不等于每页同一网格。图片为测量底图和独立复杂元素，不是整页 PPT 成品。

## 入口与优先级

- 当次明确设计要求 > 用户明确指定的风格模板 > 项目已选设计 > [长期默认设置](references/preferences.md)。上传 PPT/PDF 默认只作内容来源；没有“沿用/复刻/匹配风格”等明确指令时，不继承原文件的母版、字体、配色、背景或页序。根据论证重新组织材料。参考用途默认记录为 content，不能因为它是 PPT 就改成 style。
- 单纯讨论方法时回答问题，不生成文件。制作前读 [文案、组件与取色](references/editorial-layout-color.md)、[灵活排版与对齐](references/adaptive-layout.md)、[还原验收与阻断](references/fidelity-gates.md)、preferences.md、[母版与叠图重建](references/master-reconstruction.md)、[设计与期刊配色](references/scientific-design.md)和 [页面说明协议](references/deck-spec.md)；生图前读 [视觉流程](references/visual-workflow.md)；构建前读 [可编辑重建](references/editable-ppt.md)；交付前读 [质量检查](references/quality-checks.md)。按需读取。
- 协调当前已安装的 `imagegen` 与 `Presentations`，通过当前 skills 列表找到真实位置并读取。前者使用可调用的内置生图，后者使用 bundled `@oai/artifact-tool`。通过 `load_workspace_dependencies` 获取运行时。不硬编码缓存版本。
- 缺少必要工具时说明具体限制，保留已有文件；不要静默切换到付费 API、另一套引擎或整页图片 PPT。

## 流程

1. **材料与项目**：提取准确文字、数据、单位、原图和来源，区分事实与假设。`scripts/ppt_tools.py init --project <绝对目录>` 创建项目，不覆盖已有文件；按真实材料填写 `deck-spec.json`。
2. **内容规划与定稿**：先核实材料与科研叙事，使用已安装 humanizer-zh 的相关精简方法，仅改表达、不改科学含义。分离正文、演讲备注、制作记录，删除重复副标题与编辑口吻；保留单位、样本量、科学限定等必要信息。句子与语义换行一起设计，完成 editorial_tools.py audit 和具体 content-review 后才生图。按 [设计稿与科研校验](references/design-contract.md) 选择叙事模式。每页记录目的、准确文案、来源、元素类型和编辑要求；科研结果注明结论与证据的关系。明确总页数、受众和密度。此时只写布局意图，不先锁定元素坐标。`preflight --stage planning` 检查后探索设计，不添加虚构数据或口号。
3. **母版选择**：按 master-reconstruction.md，默认生成 3 个明确编号的母版设计图（不是 3 套完整 PPT），展示后等待用户选择。用户已明确确认具体母版时复用，不重复问。没有确认不得批量生成分页或制作正式 PPT；“直接完成”不能代替母版选择。记录 master.reference_image、哈希、approval 原话和 tokens。颜色从实际母版/分页参考图纯色区域取样，记录来源区域与哈希，建立 tokens.color_roles，不以凭印象指定的近似 HEX 替代取色。
4. **按母版逐页生图**：原始证据按真实比例预留，不设计无法容纳原图的样张。默认 per-slide。先记录 layout_family、page_rhythm 和必要的 layout_catalog，生图提示词体现本页布局与节奏。每次把所选母版作为实际风格输入，优先把原数据图、原机理流程图作为严格证据输入。逐页显示设计图；design_generation 记录 master_sha256，保持同一母版。固定元素、标题位置、文字层级与字号不逐页重定。复杂元素不能删除，按 reference_inventory 决定原生/原图/独立生图路线。设计图展示后执行 fidelity_tools.py pin 冻结，不准为方便构建换成简化稿。实际看冻结图建立独立 reference-measurements.json，分段文字、背景层、线样式和安全裁剪分别记录，不能由构建源回填。
5. **先做 PPT 母版再分页**：按 editable-ppt.md 建立原生 master/layout 和母版样页，叠入母版图校准；保存母版 PPT。先选全套最复杂的一页实际重建，展示“冻结设计图/实际 PPT 渲染”的并排与叠图，未解决问题清零、合理调整已展示并获用户验收后，记录哈希绑定的 sample-approval.json，再用同一布局或复制校准样页批量制作。母版选择不能代替复杂样页验收；已明确验收同一版样页则复用。每页先插入自己的 design_reference 底图，按像素映射建立基线；将图标+标题作为组合整体定位，对同级卡片检查等宽等距，并统一标题、分隔线和正文起点。随后按真实素材比例、阅读与对齐要求进行可追溯的局部优化；每个对象名为 `pppt:<slide-id>:<element-id>`。完整重建后从交付副本删除底图，私人草稿保留。
6. **检查和修正**：新项目设置 workflow_version="1.7"；测量完成后冻结 build/design-lock.json，构建源从同一 spec 读取准确文字、坐标与素材，预览与导出共用构建模型。逐页施工前读取设计锁，不凭记忆设样式。运行 production 预检与 `reconstruction_tools.py check`，核对母版确认、逐页母版引用、测量坐标、字号和元素清单。完成正式 finalizer、逐页渲染，再运行 inspect 比较实际对象位置/尺寸和文字。检查 inspect 的 conversion_trace，并按 design-contract.md 核对原数据、图表数据和公式；按区域叠图检查及清洁全页检查，丢元素或偏移不能仅以“可编辑”掩盖。分开验收内容、排版、颜色；检查实际语义断行、组件联合边界与跨组件基线/行数视觉关系，不能仅以无溢出判美观。检查对象相对所属区域居中、文字水平/垂直对齐，以及整段加粗是否覆盖全部中英文 runs。需要改变母版字号/固定结构时统一修改母版并重建关联页；实质性风格变化重新请用户确认。
7. **交付**：先执行 reconstruction_tools.py delivery，结构通过与视觉验收分开；逐页保留对照、具体观察、差异清单及文件哈希。缺元素、文字溢出、主体裁断、强调色丢失、分层错误、未经记录的布局偏移阻断完成；有效局部优化按调整后目标检查，不以像素差异本身阻断，未解决应说明失败页。通过后交付最终 PPTX、逐页预览、可复用项目源。PDF/演讲稿按请求或明确项目设置生成。用户要求保存风格时复制 tokens 和所选样张到长期风格目录；更新 skill 不覆盖该目录。

## 可编辑性

- 用户明确要求“只做代表性样张”才切换 representative；此时至少一张样张也必须真实生成并显示。用户明确要求“跳过生图/直接原生制作”才允许 image_design_policy=skip-explicit，并保存 image_design_skip_request 原话。“直接完成”表示通过必要验收后连续执行，不替代母版选择或复杂样页验收，也不表示跳过生图或不显示图片。

- 标题、正文、脚注为原生文本；表格和有数据的图表为原生对象；明确要求编辑的流程图用节点与连接线。无图表数据时保留原图并说明限制，不能猜数值。
- 照片、复杂插画、纹理作为独立可替换图片，不能声称内部路径可编辑。像素级还原与原生编辑冲突时优先准确内容和核心视觉关系，报告具体差异。
- 不用全页设计图充当成品，不在带正文的全页图上覆盖几个文本框冒充重建。无文字背景可以铺底，正文、证据和结构仍须原生。
- 图片中的文字和数字不是内容来源，生图与构建共用 spec 的准确文字、数据。

`使用 $personal-ppt，先给我看正文样张，我选好再制作。`

`使用 $personal-ppt，每页先生图，再重建为可编辑 PPT。`

第一版包含项目协议、提示词与检查工具；生图和原生布局由 Codex 调用现有技能完成，辅助脚本不自动把光栅图转换成全部原生对象。来源、固定提交与保留许可见 [来源说明](references/sources.md)。
